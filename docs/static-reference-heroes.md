# Static LiFei reference heroes

The homepage uses the three supplied 851 × 1848 reference artworks, including their original product photography, decorative elements, logo, icons, typography, and buttons. Assets in `public/hero` are lossless WebP conversions; the product-header assets are unaltered crops of the top 146 pixels. No artwork was generated or redesigned.

The red hero is present in the initial HTML and preloaded before the application starts. The React hero preserves the same composition and reserves the original aspect ratio. All three unchanged artworks form a horizontal carousel. Only the active slide is interactive and exposed to assistive technology; off-screen images use native lazy loading. Responsive sizing uses the stable small viewport height and safe areas, with a minimum artwork width on short landscape screens to keep the portrait reference legible. Those screens scroll rather than crop, stretch, or distort the artwork. Wider screens retain matching-color space beside the original portrait artwork rather than inventing a desktop design.

Transparent, accessible controls align with the shopping buttons and header icons already drawn in the artwork. Both shopping links use the corresponding real product route on the current domain. Loaded Shopify handles take precedence over the verified initial handles. Search, account, bag, and menu controls use the existing store callbacks. Previous and next arrows wrap in both directions. Three indicators below the image select the corresponding slide. On wider screens arrows sit outside the artwork; on phones they share the indicator row so they never cover product details or text. All controls have accessible labels and 44-pixel touch targets. Focus the carousel or its controls to use Left/Right, Home, and End. Horizontal touch or pen swipes navigate; vertical scrolling and pinch zoom remain native. Gestures beginning on links or controls are excluded to avoid accidental purchases or slide changes. No timers, autoplay, or animated transitions are used.

The existing header is sticky at the top of the page, above the carousel and other content but below modal overlays. Its original header crop supplies the unchanged logo, tagline, and icons while scrolling. The homepage artwork extends underneath that crop so there is no second visible logo or changed composition. Header dimensions remain constant during scrolling. A ResizeObserver, with resize and orientation listeners, updates the actual primary header height for anchor spacing and the mobile menu's available height. Menus open below the sticky header, scroll independently when necessary, and close with Escape. The header in existing product-detail views remains part of their non-scrolling header region.

The three Shopify product IDs in `src/data/referenceHeroes.ts` restrict the matching brand headers to their corresponding product details. Other products retain their previous detail header. Existing prices, variants, images, purchase controls, Shopify integration, and checkout logic are unchanged. The floating quick-add widget remains available after the homepage hero leaves the viewport, rather than covering the reference artwork.

## Verification

Run `npm run lint`, `npm run test:storefront`, and `npm run test:shopify` for type checking and regression tests. The platform performs the production build and deployment separately.

For visual comparison, capture each slide and compare its artwork with the corresponding file in `public/hero`. Confirm that the original header crop aligns exactly with the top of the full artwork. The navigation row is deliberately outside the original composition.

Also check 320 × 568, 390 × 844, 430 × 932, their landscape equivalents, 768 × 1024, 1024 × 768, 1440 × 900, and large desktop viewports. Confirm that artwork retains its aspect ratio, header controls align, links remain accessible, indicators and arrows work and wrap, inactive slides cannot receive focus, and there is no horizontal overflow. Scroll to the bottom and back quickly; the header must stay at the top with the same dimensions. Open and scroll the mobile menu, resize or rotate the viewport, and check keyboard focus and reduced motion. Wait longer than four seconds and move the pointer or scroll; the selected hero must not change. Real iOS Safari and Android devices should also be checked for native touch and momentum scrolling.

After platform deployment, repeat these checks on `lifeibeauty.com`, including both shopping links, homepage logo, search, account, menu, bag, browser-back navigation, the three corresponding product headers, and an unrelated product page. Local emulation is not a substitute for final production and physical-device verification.
